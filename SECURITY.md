# Security Policy

Mazo Platforms, Inc. takes the security of our platforms, developer tools, and user data seriously. We appreciate the efforts of security researchers and community members who help us maintain a safe ecosystem.

This policy applies to all public repositories, applications, and services maintained under the **@MazoPlatforms** organization.

---

## 🛡️ Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, or pull requests.**

If you believe you have found a security vulnerability in any Mazo Platforms project, please report it privately:

* **Email:** Security reports can be sent directly to `security@mazo.com` *(or open a private security advisory directly on the affected repository if available)*.
* **Response Time:** We aim to acknowledge receipt of your vulnerability report within **48 hours** and provide regular status updates regarding our investigation and remediation.

---

## 📋 Information to Include

To help us triage and fix the issue quickly, please include as much of the following information as possible:

1. **Repository & Component:** The name of the repository, package version, or service affected.
2. **Type of Vulnerability:** (e.g., Cross-Site Scripting (XSS), Authentication Bypass, SQL/NoSQL Injection, Remote Code Execution).
3. **Steps to Reproduce:** Clear proof-of-concept (PoC) code or step-by-step instructions.
4. **Impact:** An explanation of what an attacker could achieve by exploiting this issue.
5. **Suggested Fix:** (Optional) Code modifications or mitigation steps if you have them.

---

## 🔒 Responsible Disclosure Guidelines

We ask that you adhere to responsible disclosure practices:

* Give us a reasonable amount of time to investigate and address the vulnerability before making any information public.
* Avoid accessing, modifying, or deleting user data without permission.
* Do not perform Denial of Service (DoS/DDoS) attacks, spamming, or social engineering targeting our infrastructure or users.
* Maintain confidentiality regarding the security flaw until a fix has been released and coordinated disclosure is agreed upon.

---

## 🛠️ Security Update Process

When a security vulnerability is reported and confirmed:

1. **Patching:** Our core team will develop and test a fix in a private environment.
2. **Release:** A security advisory will be published along with a patched version (e.g., via NPM or GitHub Release).
3. **Credit:** Unless you request otherwise, we will publicly acknowledge your contribution in the advisory release notes for responsibly reporting the issue.

Thank you for helping keep Mazo Platforms secure!
